## 3. The decision rule (same as `CLEANUP_PLAN.md` §2)

A stale output gets one of three treatments, and the rule must be applied per file rather than per
directory:

| treatment | when |
| **REGENERATE** | its generator is live (`pipeline/`), the inputs are current, and the output is cited or read by a live instrument. The diff must be attributed. |
| **SUPERSEDE** | its generator is retired (`legacy/`) or its measurement is no longer meaningful, but the file is still cited somewhere. Add a machine-visible marker so no reader mistakes it for a result. |
| **ARCHIVE** | its generator is retired *and* nothing cites it. Move to `archive/` with the falsifying reason. |

**The marker.** A `SUPERSEDED.md` in the directory does not travel with the file. A first line that
starts `# SUPERSEDED` does, for `.md`. For `.csv` there is no such option, so the rule is: **a `.csv`
that is superseded gets moved** — to `data/analysis/_superseded/` with a `README.md` naming the
generator's new home and the Phase that retired it. `_superseded/` sorts first and is obviously not
a result.

## 4. Plan

### Task 2.1 — Inventory with provenance (no changes yet)

Produce a table: every file under `data/analysis/`, its generator (if any, live or legacy), the
commit date of the generator vs the artifact, whether a live instrument reads it, and whether a
document cites it. This is the evidence that decides REGENERATE / SUPERSEDE / ARCHIVE per file.

*Deliverable:* `data/analysis/PROVENANCE.md`, generated by a new
`pipeline/analysis_provenance.py --check` so it cannot drift (same pattern as the libation catalog).

### Task 2.2 — Regenerate what is live

Run, in dependency order, and diff each: `positional_analysis.py`, `ngram_analysis.py`,
`network_analysis.py`, `logogram_analysis.py`, `cooccurrence.py`, `word_segmentation.py`,
`morphology_scan.py`, `swadesh_search.py`, `wals_analysis.py`, `loanword_matching.py`,
`toponym_alignment.py`, `falsification_report.py`, `linear_b_mapping.py` (only if its inputs moved),
`commodity_alignment.py`, `phonetic_grid_refinement.py` (already done), `kober/*` (done).

Two rules: (a) a regeneration that changes a **conclusion** is a research event, not a cleanup — it
stops and becomes its own audit entry; (b) a regeneration that changes only **counts/inventories**
is expected (71 signs, not 138) and gets recorded as such.

*Expected:* most Phase 2–3 statistics are unchanged (they read the corpus, not the grid); anything
that enumerates the grid changes from 138 to 71 rows.

### Task 2.3 — Move the retired outputs

Create `data/analysis/_superseded/` with a README that states, per file: the generator's new path
in `legacy/`, the phase that retired it, and what superseded it. Move the group-A files there:
`ml/`, `verification/`, `eteocretan/`, `anatolian_search/`, `phylogenetic/`, `egyptian_bridge/`,
`commodity_decoding/commodity_report.md`, `frequency_constraints/`.

Keep in place: `commodity_decoding/{enrichment_audit,cross_site_replication}.py` and their inputs —
they are live audit instruments (Phase 14/14.1) and are cited by the audit trail.

### Task 2.4 — Cite-check the moved paths

Every document that names a moved file gets a pointer. Historical audit entries
(`verification_audit.md`, `oracle_repair_report.md`) are **not** edited — the `_superseded/README.md`
is the redirect, and `PROVENANCE.md` is the map.

## 6. Risks

| risk | mitigation |
| a regeneration changes a conclusion | stop; that is a research finding, not cleanup. Record it and re-plan |
| moving a file breaks a live import | move only outputs, never `*.py`; guard 24 covers provenance, and `pipeline/` imports nothing from `data/` |
| `_superseded/` becomes a dumping ground | the README must state the generator's new home and what replaced it, or the file is archived instead |
| re-running ML needs torch and hours | ML outputs are group A (retired generator): SUPERSEDE, not regenerate. Restarting Phase 4 is open item 7 and is not step 2 |
