## 3. Plan

### Finding 9 — a blocking defect found while implementing Task 1.1

**Five real signs are invisible to every grid, because the grid lineage upper-cases sign IDs while
the corpus and the Unicode mapping use lower-case suffixes.**

| sign | corpus occurrences | codepoint | in the 138-row grid | in the "honest" 69-row grid |
| `AB 21f` | 22 | U+10610 | as `AB 21F` (unresolvable) | no — purged as a phantom |
| `AB 21m` | 8 | U+10611 | no | no |
| `AB 22f` | 15 | U+10613 | as `AB 22F` (unresolvable) | no — purged as a phantom |
| `AB 22m` | 4 | U+10614 | no | no |
| `AB 23m` | 7 | U+10616 | no | no |

Mechanism: `languages/linear-a/mapping.csv` and `lineara_full.db` both spell these **lower-case**
(`AB 21f`), and the two agree with each other exactly. `phonetic_grid_refinement.clean_bennett()` and
the Phase 7/8 grid writers spell them `AB 21F`, and `unicode_utils.normalize_bennett()` upper-cases
any ID that does not match its `AB <digits>` pattern — so `bennett_to_unicode('AB 21F')` returns
**None** and `corpus_counts()['AB 21F']` is **0**. The Phase 11 purge therefore dropped `AB 21F` and
`AB 22F` as "no valid codepoint; 0 corpus occurrences", which is true of the uppercase *strings* and
false of the *signs*. **37 real occurrences were removed from the grid the project calls honest, and
those two signs' CONFIRM statuses went with them.**

Consequences for the expected numbers: the honest grid is **71 signs, not 69** (the 69 correct rows
plus the two falsely purged F-signs); the three M-signs are a **completeness gap** to be reported
rather than quietly invented — the grid is evidence-driven and no evidence file names them.

### Tasks

Tasks are ordered by dependency. Each ends with a measurement, and nothing is regenerated without
attributing the diff (EXPERIMENT_PROTOCOL §3).

### Task 1.0 — One canonical sign ID, and case-safe joins *(blocking; found during 1.1)*

Finding 9 has to be fixed before any grid is regenerated, or the new grids inherit it.

1. `unicode_utils`: make the Bennett lookups case-insensitive and add `canonical_bennett()`, which
   returns the spelling the mapping file uses (`AB 21f`, not `AB 21F`). The mapping is validated
   against the Unicode names by `pipeline.cli unicode validate`, so it is the authority.
2. `purge_grid`: index the corpus counts case-insensitively and resolve each ID to its canonical
   form before deciding. The *rule* does not change; the implementation stops mistaking a case
   variant for a phantom.
3. `phonetic_grid_refinement.clean_bennett()`: stop upper-casing the suffix; delegate to
   `canonical_bennett()`.
4. Guard 22 (new): **no grid may contain an ID that fails to resolve against the mapping or the
   corpus**, checked case-insensitively so it cannot be satisfied by spelling luck.
5. Guard 23 (new): report the **completeness gap** — corpus syllabograms with a codepoint that no
   grid lists (`AB 21m`, `AB 22m`, `AB 23m` today). Reported, not enforced: inventing rows is worse
   than a documented gap.

*Expected:* the refined grid emits `AB 21f`/`AB 22f` at their true spellings; the historical purge
reconstruction gains them too; grid size 69 → 71.

### Task 1.1 — Purge at the generator, not at the artifact

`phonetic_grid_refinement.py` builds `all_signs` as a union of evidence dictionaries (LB, CM,
positional, n-gram, misaligned, CM grid), which is where the 138 rows come from. Filter that union
to **real signs** — a valid Unicode codepoint *and* ≥ 1 occurrence in the corrected corpus — before
writing anything.

Outputs affected (all three are written by this module): `refined_phonetic_grid.csv`,
`grid_changes_from_ab.csv`, `misvalued_signs_resolution.csv`.

*Expected:* 138 → 71 rows; CONFIRM 40 → ~37 (the five phantom CONFIRMs AB 12/15/18/35/52 go; the
F-signs return); `misvalued_signs_resolution.csv` loses its phantom row (AB 36 `jo`).

*Note:* the module is a pure producer — it reads no grid — so there is no circularity risk.

### Task 1.3 — Re-derive the Phase 8 grid and settle its two filenames

Currently: `grid_expand.py` reads `refined_phonetic_grid.csv` → writes `expanded_grid.csv` (138 rows,
deprecated) → `purge_grid.py` filters → `expanded_grid_purged.csv` (69 rows, canonical).

After Task 1.1 the input is already honest, so the second file is generated by filtering an
already-filtered grid. **Decision: `grid_expand.py` writes the canonical grid directly under the
name everything already references** — `expanded_grid_purged.csv` — and `expanded_grid.csv` is
retired as a *frozen historical input*:

- move the committed 138-row `expanded_grid.csv` to `data/analysis/bootstrapping/expanded_grid_legacy_138.csv`
  (frozen; the Phase 11 purge result must stay verifiable against the thing it was computed from);
- `purge_grid.py` keeps its rule and gains `--against <frozen legacy grid>` so guard 15 becomes
  "the Phase 11 purge result is reproducible from the frozen legacy grid", which is what that guard
  is actually for;
- add guard 20: **the canonical grid contains no phantom rows** (codepoint + occurrence, checked
  directly) — the invariant that matters going forward.

*Expected:* `expanded_grid_purged.csv` = 71 rows, **~54 CONFIRM** (findings 1–4 and 9), regenerable
from `refined_phonetic_grid.csv` by one command.

## 5. Risks and rollback

| risk | mitigation |
| the LA oracle number changes, and it is a recorded result | record the movement and its cause in Phase 18; the *verdict* is what the claim rests on and it does not move |
| retiring `expanded_grid.csv` breaks a reference | grep for the name before the move; only `purge_grid.py`, `guards.py`, `oracle_diagnose.py` and docs read it |
| regenerating changes a product whose change I do not understand | every regenerated file is diffed and each diff attributed (fix vs drift); unexplained diffs stop the step |
| the legacy freq-constraints chain cannot be re-run (its module is in `legacy/`) | regenerate from `legacy/` explicitly and record the dependency, or drop the term with the reason recorded |
| scope creep into step 2 (regenerating the 25+ stale *outputs*) | out of scope here: step 1 fixes the grids and the LA instruments, step 2 handles downstream outputs |

**Rollback:** every change is a git commit with the measurement in its message. The 138-row legacy
grid is preserved (moved, not deleted), so the Phase 11 purge result stays reproducible.
